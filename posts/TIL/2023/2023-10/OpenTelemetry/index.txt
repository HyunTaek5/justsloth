<h3>OpenTelemetry의 개념</h3>
<ul>
<li>
<h4>시그널</h4>
<ul>
<li>다양한 종류의 원격 측정 데이터를 담을 수 있는 개방형 규격을 제공하기 위해 관심의 범주를 구성하는 용어</li>
<li>자기 자신의 값을 제공하도록 설정할 수 있는 독립 컴포넌트</li>
<li>각 시그널이 제공하는 내용
<ul>
<li>시그널 구현을 위한 스펙 문서</li>
<li>구현상 시그널을 나타내는 데이터 모델 표현
<ul>
<li>데이터 모델 : 특정한  시그널을 구성하는 컴포넌트의 표현 방식을 정의</li>
</ul>
</li>
<li>개발자가 코드에서 사용할 API</li>
<li>API를 사용해 원격 측정 데이터를 만들 때 사용하는 SDK</li>
<li>일관성 있는 고품질 데이터를 얻기 위한 시맨틱 표기법
<ul>
<li>시맨틱 표기법 : 여러 형태의 애플리케이션이나 워크로드에 관한 정의를 제공하여 원격 측정의 일관성을 개선하는 방법
<ul>
<li>어떤 원격 측정이 이뤄져야 하는지와 데이터를 어떻게 식별할 것인지에 관한 정보를 제공</li>
<li>시맨틱 표기법이 다루는 프로토콜/애플리케이션 형태
<ul>
<li>HTTP</li>
<li>DB</li>
<li>Mq</li>
<li>FaaS(Function-as-a-Service)</li>
<li>RPC(Remote-Procedure-Call)</li>
<li>Process 지표</li>
</ul>
</li>
</ul>
</li>
</ul>
</li>
<li>계측 라이브러리</li>
</ul>
</li>
<li>OpenTelemetry에서 최초로 정의한 시그널
<ul>
<li>추적</li>
<li>메트릭</li>
<li>로그</li>
<li>배기지(baggage)</li>
</ul>
</li>
</ul>
</li>
</ul>
